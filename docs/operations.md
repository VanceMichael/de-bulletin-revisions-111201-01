# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 持续追踪

`track` 命令对给定链接各抓取一次，可反复执行实现轮询；链接凭据（ETag、
Last-Modified、本链接正文缓存）都保存在数据库，进程内无状态，可随时重启。
`--allow` 可重复传入，只有目标属于这些来源的 canonical 声明才会被采信。

版本切换分两阶段：正文先以内容寻址落库（幂等），随后版本、索引头、链接凭据
在单个 BEGIN IMMEDIATE 事务内生效。两阶段之间进程退出时，编辑看到的仍是旧版本，
重启重采后同一正文只产生一个版本、一次有效切换。多进程并发写同一数据库时，
写事务串行化，重复更正按 (条目, 正文内容) 去重。

撤稿（410）与暂时失败（5xx、连接异常）分开记录：撤稿翻转条目状态并保留理由与
来源时间，历史版本仍可查询；暂时失败只写入事件流与链接状态，不影响当前版本。

测试钩子：设置环境变量 `COLLECTOR_TEST_CRASH_AFTER_RAW=1` 后，`track` 会在
正文保存后、索引更新前立即退出进程，用于演练崩溃恢复；正常使用时不要设置。
